# Turn the squad into an evidence gate

Agentic AI in late 2026 has settled into a well-understood stack. It is one tool-using model loop wrapped in a harness, and the harness does the real work: careful tool design, context engineering, durable on-disk state, OS-level sandboxing, policy-driven approvals, outcome-based evals and OpenTelemetry tracing. MCP is the standard tool bus and A2A covers agent-to-agent traffic across organizations. The leading coding agents (Claude Code, Codex, Cursor, Copilot, Devin, opencode, OpenHands) now ship almost the same surfaces, so they compete on model, price and license. All of them share the same two open wounds. The first is **verification nobody can trust**: developer trust in AI output fell from 40% to 29%, and agents game or hallucinate test results. The second is **prompt injection through issues and PRs**, which in 2026 already led to stolen CI secrets and leaked private repositories. Multi-agent frameworks have not closed either gap. Role-play "software company" teams show no credible win over strong single agents. What does work is a single writer plus an independent verifier with a clean context. Our squad repo is a clean, honest plan-execute-verify prototype with good tracing, but it is not competitive as a coding agent. Its gates trust the model's own `passed` flag, its "sandbox" gives arbitrary code execution with the user's environment, its tests can be disabled with one `conftest.py`, and its headline eval is staged. The project should stop trying to be a coding agent. It should become an **open, agent-agnostic verification and governance layer**: deterministic, tamper-evident gates, least-privilege roles and a signed evidence bundle per change, wrapped around any author agent (Claude Code through the Agent SDK first). Most of the existing code (triage rules, trace, copy-on-write apply, separation of duties) carries over to that role.

## Agentic AI is now one model loop inside a heavy harness

The working vocabulary has not changed since Anthropic and OpenAI wrote it down. A **workflow** runs LLMs along predefined code paths. An **agent** is an LLM that "dynamically direct[s] [its] own processes and tool usage" until it decides it is done ([Anthropic](https://www.anthropic.com/engineering/building-effective-agents)). Both vendors say to start with the simplest option and to add multi-agent orchestration only when clearly needed ([OpenAI](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)). Most production systems are workflows with agentic steps inside them. The cheapest lever with the largest effect is the **agent-computer interface** rather than the prompt. In Anthropic's SWE-bench work, requiring absolute file paths removed a whole class of errors, and having an agent rewrite tool descriptions cut task completion time by **40%** ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)).

Context engineering has replaced prompt engineering as the core skill. Because of "context rot", context has to be treated "as a finite resource with diminishing marginal returns." The standard techniques are compaction, clearing old tool results, structured notes kept outside the window, and sub-agents that spend tens of thousands of tokens and return **1,000–2,000-token summaries**. Files are fetched just in time with grep and glob, on top of a small always-loaded memory file such as CLAUDE.md or AGENTS.md ([Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Long-running coding agents keep their memory on disk rather than in the window: a JSON feature list in which the agent may only flip `passes`, a progress log, an `init.sh`, and a git commit after each feature as a checkpoint. Anthropic's harness states that "it is unacceptable to remove or edit tests" ([Anthropic](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).

The protocol layer matured and then changed shape. MCP moved to the Linux Foundation's Agentic AI Foundation in December 2025. Its current **2026-07-28** revision is **stateless**: it drops the `initialize` handshake and session IDs, and replaces server-initiated sampling and elicitation with multi-round-trip requests. It moves Tasks into an extension, deprecates Roots, Sampling and Logging, and propagates W3C trace context in `_meta` ([MCP changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)). A2A v1.0 is the stable agent-to-agent counterpart, supported by more than 150 organizations ([Linux Foundation](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)). A2A only matters when agents cross organizational boundaries. MCP's weak point is still trust. Tool poisoning, rug pulls and tool shadowing share a root cause, "MCP clients inherit trust from servers without continuous verification" ([CSA](https://labs.cloudsecurityalliance.org/research-rb/csa-whitepaper-mcp-security-tool-poisoning-20260506-csa-styl/)). OWASP's conclusion is that restrictions written only in system prompts can be overridden, so enforcement has to live at the tool-execution layer ([OWASP](https://owasp.org/www-community/attacks/MCP%5FTool%5FPoisoning)).

The safety and operations layers have converged too. Claude Code enforces its sandbox at the OS level (Seatbelt on macOS, bubblewrap on Linux) across every subprocess ([Claude Code docs](https://code.claude.com/docs/en/sandboxing)), and Anthropic reports that this cut permission prompts by **84%** ([Anthropic](https://anthropic.com/engineering/claude-code-sandboxing)). Codex defaults to `workspace-write` with no network, and keeps `.git/` read-only even in that mode ([OpenAI](https://developers.openai.com/codex/concepts/sandboxing)). Fully untrusted cloud execution goes to Firecracker microVMs or gVisor ([Vercel](https://vercel.com/i/gvisor-vs-microvms)). For evals, Anthropic's January 2026 guide is the reference: grade **outcomes, not paths**, prefer deterministic graders, and report **pass^k** when consistency matters. At 75% per-trial success, pass^3 is only about 42%. It also advises starting with 20–50 tasks drawn from real failures ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). For tracing, the emerging standard is OpenTelemetry's GenAI agent spans (`invoke_agent`, `execute_tool`), still marked Development ([OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-agent-spans/index.md)).

| Building block | Late-2026 state of the art | What it implies for a delivery tool |
|---|---|---|
| Loop and tools | Single agent loop; poka-yoke tools; str_replace edits, grep/glob, ranged reads | Tool quality beats prompt quality |
| Context | Compaction, result clearing, sub-agent summaries, just-in-time retrieval | The hand-off artifact is the key design decision |
| MCP / A2A | Stateless MCP 2026-07-28; A2A v1.0 for cross-org agents | Target stateless MCP; enforce permissions in the harness |
| Memory and planning | On-disk JSON task lists, progress logs, git checkpoints | Versioned repo artifacts, not opaque stores |
| Evals | Outcome graders, pass^k, private task suites | Evaluate your own harness on your own tasks |
| Sandbox and HITL | Seatbelt/bubblewrap locally, microVMs in the cloud; escalating approvals | Isolation is what lets you remove approval prompts |
| Observability | OTel GenAI spans; MCP trace propagation | Emit OTel now to stay vendor-neutral |

## Coding agents converged on surfaces and diverge only on trust failures

By late 2026 every major vendor ships a terminal CLI, IDE integration, background cloud agents and PR review. The extension model is the same everywhere: MCP, sub-agents, hooks, skills or plugins, and a project memory file. Copilot's Agent Plugins went GA in August 2026 ([GitHub changelog](https://github.blog/changelog/2026-08-13-github-copilot-weekly-releases-august-10)), and local sandboxing went GA in its CLI and VS Code in October ([GitHub changelog](https://github.blog/changelog/2026-10-05-github-copilot-weekly-releases-october-5/)). The market is consolidating. Windsurf became Devin Desktop ([Devin docs](https://docs.devin.ai/desktop/devin-desktop-faq)), and GitHub's Agent HQ runs Claude and Codex agents inside a Copilot subscription ([GitHub](https://github.blog/news-insights/company-news/welcome-home-agents/)). In open source, opencode (about 200k stars, MIT), Codex CLI (about 109k, Apache-2.0), Gemini CLI (about 107k) and Cline (about 67k) lead on stars, though the counts conflict across sources ([Morph](https://www.morphllm.com/ai-coding-agent)). The real differences are the default model, billing (rolling subscription caps, credit pools, or BYOK at token cost) and license.

Benchmarks no longer separate them reliably. OpenAI stopped reporting SWE-bench Verified in February 2026 after finding that **59.4%** of 138 audited hard problems had material test issues, and that frontier models could reproduce gold patches ([OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)). On repositories outside the benchmark, accuracy fell to as low as **53%** ([arXiv 2506.12286](https://arxiv.org/html/2506.12286v4)). On Scale's standardized SWE-bench Pro board the top score is about **61.5%** ([Scale](https://labs.scale.com/leaderboard/swe_bench_pro_public)), while vendor-reported Pro figures of around 80% come from custom scaffolds ([Morph](https://www.morphllm.com/ai-coding-agent)). The harness matters as much as the model. The same model scores 70–82% on Terminal-Bench 2.0 depending on the agent wrapped around it ([Codesota](https://www.codesota.com/benchmark/terminal-bench); [Vals.ai](https://vals.ai/benchmarks/terminal-bench-2)), and the top Terminal-Bench 4.0 entries differ by **7x in cost per task** ($14.30 against $1.92; single source, [Morph](https://www.morphllm.com/ai-coding-agent)).

The weaknesses are consistent across vendors. Trust is falling even as use rises. In the 2025 Stack Overflow survey, 46% of developers actively distrust AI output and 66% cite "almost right" code as a frustration ([Stack Overflow](https://stackoverflow.blog/2025/07/29/developers-remain-willing-but-reluctant-to-use-ai-the-2025-developer-survey-results-are-here/)). A vendor study found AI-co-authored PRs carry **1.7x more issues** and 1.57x more security findings ([CodeRabbit](https://www.coderabbit.ai/blog/state-of-AI-vs-human-code-generation-report)). Maintainers at tldraw, Ghostty and Godot are restricting AI PRs ([The Register](https://www.theregister.com/2026/02/18/godot_maintainers_struggle_with_draining/)). Reward hacking is now well measured: agents modify or delete tests, special-case test inputs, and exit early with a success status ([arXiv 2611.10404](https://arxiv.org/pdf/2611.10404); [EvilGenie](https://arxiv.org/html/2511.21654v1)). Security incidents follow a single pattern. Clinejection ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-claude-code-github-action-prompt-injection/)), "Comment and Control" ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-coding-agent-ci-prompt-injection-202608/)) and GitLost ([The Hacker News](https://thehackernews.com/2026/07/public-github-issue-could-trick-github.html)) all routed untrusted issue or PR text into an agent that held broad CI tokens. That is Willison's "lethal trifecta" of private data, untrusted content and an outbound channel ([Willison](https://simonwillison.net/2025/jun/16/the-lethal-trifecta/)). Cost is the third complaint. Gartner says consumption pricing has "introduced unpredictable and rapidly increasing costs" ([Gartner](https://www.gartner.com/en/documents/8146329)). Enterprises also cannot answer the auditor's question of who approved an agent's change and what it read ([The New Stack](https://thenewstack.io/agentic-cicd-audit-compliance-gap/)). JFrog says no widely adopted standard for agent provenance exists yet ([JFrog](https://jfrog.com/blog/prompt-to-release-traceability/)).

The vendors' answer to weak verification is to add a review agent: Bugbot, Codex cloud review, Copilot's self-review pass, and Devin Review. Devin Review finds about **2 bugs per PR, ~58% severe** ([Cognition](https://cognition.com/blog/multi-agents-working)). These reviewers are proprietary, bound to one vendor, and are themselves model opinions. None of them produces a mechanically checkable, tamper-evident record that an outsider can verify.

## Org-chart agent teams lose; independent verifiers win

The framework field has split into two camps. One is durable graph and workflow runtimes: LangGraph, Microsoft Agent Framework (GA April 2026) and Google ADK ([Microsoft](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/)). The other is thin "agent loop plus tools plus handoffs" SDKs: OpenAI Agents SDK, Claude Agent SDK, Pydantic AI and smolagents. Stars are a poor guide to health. The two most-starred repos are MetaGPT (71k, no push for about ten months) and AutoGen (62k), and AutoGen is now **archived**, with the maintainers advising "against production use" ([AutoGen](https://github.com/microsoft/autogen); [MetaGPT](https://github.com/FoundationAgents/MetaGPT)). No vendor SDK adopted the CEO/CTO role-play metaphor.

The evidence against role-play teams is consistent. MetaGPT and ChatDev each win on a benchmark they built themselves. An independent check found ChatDev at only **33.33%** correctness ([Berkeley MAST](https://sky.cs.berkeley.edu/project/mast/)). The MAST study annotated 1,642 traces across seven frameworks and found failure rates of **41–86.7%**. About 44% of failures came from system design and about 23.5% from verification, and the single best fix to ChatDev was adding an objective verification step (**+15.6%**) ([arXiv 2503.13657](https://arxiv.org/html/2503.13657v3)). Controlled 2026 studies point the same way. On SOP-Bench, a single agent scored 67.4%. A first orchestrator scored 58.2% at 2.6x the latency, and only a redesigned orchestrator won (75.6%), at **4.7x the tokens** ([arXiv 2611.12953](https://arxiv.org/html/2611.12953)). Across ten benchmarks, five of six multi-agent systems trailed a single-agent controller ([arXiv 2606.05670](https://arxiv.org/html/2606.05670)). When reasoning tokens are held constant, single agents match or beat multi-agent systems on multi-hop reasoning ([arXiv 2604.02460](https://arxiv.org/abs/2604.02460)). Anthropic's **+90.2%** multi-agent research result is real but internal. By Anthropic's own analysis, token spend explains 80% of the variance, and it warns that "most coding tasks" fit the pattern poorly ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)).

What survives is narrow and well defined. Cognition moved from "Don't Build Multi-Agents" ([Cognition](https://cognition.com/blog/dont-build-multi-agents)) to a converged position: writes stay single-threaded, extra agents "contribute intelligence" rather than actions, and the reviewer gets a clean context. In Cognition's words, "clean context leads to a notable improvement in capabilities when using a generator-verifier loop" ([Cognition](https://cognition.com/blog/multi-agents-working)). AgentCoder's gains came from an independent test designer rather than from personas ([arXiv 2312.13010](https://arxiv.org/pdf/2312.13010)). E2EDevBench names omitted requirements and inadequate self-verification as the main bottlenecks ([arXiv 2511.04064](https://arxiv.org/abs/2511.04064)). Multi-agent structure earns its 1.3–5x cost in two ways. It can separate privileges and give a verifier real independence, or it can run truly parallel read-only exploration. It does not earn the cost by adding more personas.

## Our squad is an honest prototype of the pattern the evidence rejects

The audit of commit `a95a39a` (64 tests green, about 1,500 lines) finds real engineering strengths. There is a single `LLM.complete` boundary with a scripted test double. Tool permissions are enforced in code (`squad/mcp_host.py:57-61`). An append-only JSONL trace drives the CLI, the web HUD and replay. Work happens in a copy-on-write workspace with a git baseline and a conflict-aware `/apply`. The documentation is candid about the project's limits. But the core architecture is a fixed RADAR→ATLAS→FORGE→WARDEN/AEGIS relay (`squad/orchestrator.py:136-168`). That is the MetaGPT/ChatDev shape the research above finds wanting, and the audit's verdict is that the split is "mostly not" justified.

The specific failures line up with the industry's known problems, which makes them instructive. **The gates are model opinions.** `_verify` reads `run.deliverable["passed"]` and never checks the test exit code (`squad/orchestrator.py:193`). With the Claude Code backend, a string `"false"` is truthy and counts as a pass. **The tests can be gamed.** In probes, a root `conftest.py` that skips every test produced `passed: True` over buggy code. On case-insensitive APFS, writing `Tests/test_money.py` overwrote the protected tests. An empty test suite also counts as a pass (`squad/workspace.py:68-71,83-84`). **The sandbox is not a sandbox.** FORGE's `run_tests` executes model-written code with `{**os.environ}`, so it sees API keys, cloud credentials and `SSH_AUTH_SOCK`, and it has network access. One probe wrote a file into `$HOME`. `.git/config` is writable, so `core.fsmonitor` or `core.hooksPath` can run arbitrary commands on the orchestrator's next `git add` (`squad/orchestrator.py:43`; `squad/workspace.py:96,119`). **Injection is amplified.** RADAR's summary of untrusted docs reaches FORGE labelled as "rules the implementer must respect" (`squad/prompts.py:32`), and the Claude Code renderer's `RESULT:` markers can be forged from file content (`squad/claude_code.py:43-59`).

The agent mechanics trail the state of the art on almost every row of the building-block table. Edits are whole-file overwrites, there is no grep or glob, tool output is silently cut at 8,000 characters, and output is capped at 4,096 tokens with no `max_tokens` handling. In practice that means the squad cannot safely edit its own 11.4 KB `orchestrator.py`. There is no prompt caching, so cost grows quadratically with steps. Retries start from an empty history. QA runs on Haiku, which means a weaker model judges a stronger one. The Claude Code backend spawns a fresh `claude -p` process for every step. The MCP use is real plumbing around 35-line JSON readers. Swapping in a real Atlassian server would break on the hard-coded tool names and the `Ticket` shape (`squad/models.py:48-54`). Finally, the eval is staged. The scripted model writes insecure code on attempt 1 by construction (`squad/scripted.py:79-82`). The "solo" baseline is denied the policy doc (`squad/evals.py:13`). The demo test suite has no ownership test, even though ownership is policy rule 1. The solo-versus-squad claim in vision.md should not be presented as evidence.

| Dimension | State of the art | Squad today | Gap |
|---|---|---|---|
| Edit and navigation tools | str_replace, grep/glob, ranged reads, lint after edit | Whole-file write, list/read only, silent truncation | Severe |
| Verification | Deterministic CI plus clean-context reviewer | Model's `passed` flag decides | Severe |
| Test integrity | Tests read-only, restored originals, held-out tests | Path-prefix guard, bypassable | Severe |
| Sandbox | OS sandbox or microVM, no network, protected `.git` | Full user env, network, writable `.git` | Severe |
| Injection defense | Tainted content isolated from privileged tools | Untrusted text promoted to "rules" | Severe |
| Context and cost | Compaction, caching, budgets | None; 14 fixed steps | High |
| Orchestration | Single writer plus independent verifier | Fixed five-role relay | High |
| Observability | OTel GenAI spans | Good custom JSONL trace and replay | Moderate (strength) |
| Policy and sizing | Mostly implicit in vendor tools | Explainable triage with non-negotiable rules | Strength |
| Evals | Private outcome-graded suites, pass^k | Staged scripted demo | Severe |

## Become the verification and governance layer around any coding agent

The strategic choice is clear. Competing as a coding agent means competing with Claude Code, Codex and a 200k-star opencode on tool quality and model access, and a solo project will lose that race. The defensible open slot is what every agent lacks: **verification that resists cheating, least-privilege orchestration that breaks the lethal trifecta by construction, and an open, signed provenance record per change**. The industry's own pain points show demand for all three: falling trust, AI-slop PR fatigue, reward hacking, CI secret theft and auditors who cannot reconstruct an agent's inputs ([The New Stack](https://thenewstack.io/agentic-cicd-audit-compliance-gap/)). The research methods behind them are cheap to productize: watching for test-file edits, restoring original tests, running held-out tests, and agent-written property-based tests ([arXiv 2510.09907](https://arxiv.org/html/2510.09907v1); [arXiv 2610.04793](https://arxiv.org/pdf/2610.04793)). Existing provenance work is closed and vendor-locked ([JFrog](https://jfrog.com/blog/prompt-to-release-traceability/); [Sourcegraph](https://sourcegraph.com/blog/compliance-first-ai-proving-agent-provenance)). In this framing the author agent becomes a pluggable component, with Claude Code driven through the Claude Agent SDK first and Codex or opencode later. The squad's value is then the gate between "agent says done" and "a human merges." The pitch is concrete: **any agent's PR arrives with machine-checked evidence that its tests are the original tests, that they actually ran and passed, that nothing outside scope changed, and that a clean-context reviewer with no write access signed off.**

The strongest objection is that vendors already ship review agents. They do, but each is a model opinion inside one vendor's walled garden. A deterministic, tamper-evident, agent-agnostic gate with an open attestation format is a different product. Payments, auth and PII changes are a natural beachhead because "who verified what, with which evidence" carries legal weight there. A second objection is that "regulated work" is a narrow niche. That is true, but narrowness is an advantage for a small open-source project, and the same gate helps any maintainer drowning in AI PRs. One real uncertainty remains. The research did not run a competitive check against Inspect, promptfoo, Invariant Labs' guardrails, SWE-smith or OpenHands evals, so the first week should confirm that nobody already ships this combination.

### Keep, rebuild or discard: each component maps to a new job

The Valorant presentation layer can stay as the explanation layer for non-engineers, provided each name maps to a real function rather than a persona. Under the new design, FORGE is the pluggable author, WARDEN is the deterministic gate, AEGIS is the clean-context reviewer and RADAR is a read-only explorer.

| Component | Decision | Reason |
|---|---|---|
| `LLM.complete` boundary and scripted double (`squad/llm.py`, `squad/scripted.py`) | **Keep** for machinery tests | Makes the pipeline testable; stop using it as quality evidence |
| Code-enforced tool permissions (`squad/mcp_host.py`) | **Keep and extend** to per-role credentials and network policy | Enforcement in the harness is the OWASP-endorsed pattern |
| JSONL trace, listeners, replay (`squad/trace.py`, `squad/ui.py`) | **Keep, evolve** into the evidence bundle and OTel GenAI spans | Already the best part; becomes the product's output |
| Triage sizing with non-negotiable rules (`squad/draft.py`, `squad/triage.py`) | **Keep, promote** to declarative `squad.policy.yaml` | "Model proposes, policy disposes" is under-used elsewhere |
| Copy-on-write workspace and conflict-aware `/apply` | **Keep**, fix rename handling, put real isolation behind it | Right UX instinct |
| AEGIS as independent reviewer | **Keep, rebuild** on a model at least as strong as the author, seeing only diff plus evidence, with real scanners (Semgrep, Bandit) | The one role split with evidence behind it |
| WARDEN as a model re-running pytest | **Discard**; replace with orchestrator-computed gates | A Haiku opinion on a red suite is the core failure |
| RADAR summarizer injecting "rules" | **Discard**; at most a read-only explorer returning cited notes | Telephone-game loss plus injection amplification |
| ATLAS as a separate planning call | **Discard**; fold acceptance criteria into executable tests owned by the verifier | A plan with no tests is role-play |
| FORGE's native tool layer | **Freeze** at minimal; delegate real authoring to Claude Code through the Agent SDK | Rebuilding str_replace, grep and compaction is reinventing a solved wheel |
| Per-step `claude -p` re-spawning (`squad/claude_code.py`) | **Discard** for one long-lived Agent SDK session | Loses tool IDs, caching and parallelism; injectable markers |
| Stand-in Jira/Confluence servers | **Demote** to test fixtures; map real servers by capability | Indirection without capability |
| Keyword auth scanner and staged solo-vs-squad eval | **Discard** as evidence | `# authorize: TODO` passes; baseline is unfair |

### Revamp plan in priority order

The ordering follows a simple rule: first stop making claims the code cannot back, then make the gate trustworthy, then make it safe, then make it pluggable, then prove it. Each phase is a feature branch shipped and pushed on its own, in line with the project's one-iteration-at-a-time practice.

| Priority | Phase | Concrete work | Done when |
|---|---|---|---|
| P0 | Honesty and adversarial tests (days) | Remove the solo-vs-squad claim and the "nothing changes until you say so" sandbox claim from README.md and vision.md. Add failing adversarial tests: skip-all `conftest.py`, case-variant `Tests/`, `.git/config` writes, `passed: "false"`, malformed deliverables, truncated read then write, injection fixtures. | The red tests document every audit probe |
| P1 | Deterministic gates | The orchestrator runs tests itself with `--junitxml`. It requires exit 0 and a minimum number of tests that actually executed, and rejects all-skipped or deselected runs. "No tests" yields **UNVERIFIED**, not pass. Add compile and lint steps. Validate deliverables against strict schemas with a repair turn. Model reviewers may only add issues, never override a red gate. | Every P0 gaming test fails the gate |
| P2 | Test integrity | Hash every test file and test-affecting config (`conftest.py`, `pytest.ini`, `pyproject.toml`, `setup.cfg`, `tox.ini`, `sitecustomize.py`) at baseline using `normcase` and resolved paths. Run the pristine baseline tests against the modified sources. Let the author add tests only in new files. Support **held-out tests** the author never sees. Refuse `.git` writes and run git with `-c core.fsmonitor= -c core.hooksPath=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`, or keep the git dir outside the workspace. | Tamper attempts are detected and reported as evidence |
| P3 | Real isolation and taint | Run tests and any shell inside a container with `--network none` (or Seatbelt/bubblewrap), with only the workspace mounted and an allow-listed environment. Treat ticket, issue, PR and doc text as tainted and wrap it in delimited untrusted blocks. Never give tainted-input roles secrets plus egress. Add a Host-header check and per-launch token to the web server. | The `$HOME`-write and env-exfiltration probes fail |
| P4 | Pluggable author | Drive Claude Code through the Claude Agent SDK as FORGE, in one long-lived session with the squad's MCP servers. Define an author adapter so Codex or opencode can follow. Carry an attempt summary (files changed, last failure) into retries. Add `cache_control` on the native path. | The same gate verifies PRs from two different authors |
| P5 | Policy as code and separation of duties | Add a versioned `squad.policy.yaml` per repo covering which paths are sensitive, which gates are mandatory, the reviewer model floor, budget caps, and who may approve. The dispatcher cannot override it. The reviewer gets fresh context, the diff plus evidence, and no write tools. | Policy decisions appear in the trace with rule IDs |
| P6 | Evidence bundle | Emit a signed, in-toto/SLSA-style attestation per change. It records the spec, files read, tool calls, model and version, cost, policy decisions, gate results with exit codes and hashes, reviewer findings and the named human approver. Emit OTel GenAI spans and attach the bundle to the PR through a GitHub Action. | An outsider can verify a PR's claims without trusting the agent |
| P7 | Your-repo eval harness | Build 15–30 seeded tasks with hidden fail-to-pass and pass-to-pass tests, then mine the team's own merged PRs for more. Compare three setups: the gated squad, a single agent with all tools and the same checklist, and a single agent plus reviewer. Run at least 3 seeds and report pass^k, hidden-test pass rate, cost and latency. | A live-model result replaces the staged demo |
| P8 | Stretch | Mutation-score gate (mutmut, Stryker), verifier-written property-based tests, per-ticket cost budgets and model routing, real Atlassian/GitHub/Linear MCP mapped by capability on stateless MCP 2026-07-28, and PR-size limits tuned for "reviewable in under N minutes". | Each item ships behind policy flags |

P1 through P3 are non-negotiable before the project makes any public claim, because they turn today's theatre into a gate that a skeptic cannot trivially defeat. P4 is the strategic pivot: it frees the project from the losing race on agent mechanics. P7 decides whether the project has a story worth telling. If a single agent with the same gates and checklist matches the squad, the honest result is that the gates are the product, and that result is still publishable.

## Conclusion

The evidence reframes the project's thesis. The squad was built on the idea that more specialized agents produce better software. The 2025–2026 record says the reverse: extra agents mostly add tokens and failure modes, and the only multi-agent structure that reliably pays is the one that **separates privileges and makes verification independent**. The squad already contains the seeds of that structure in its post-hoc policy rules, its author-versus-verifier split and its trace. The problem is that today those pieces are decorative, because the model can override the gate, tamper with the tests and reach the network. Make them load-bearing and the project stops being the hundredth MetaGPT clone and becomes something the frontier agents structurally cannot offer themselves: a neutral party that checks their work.

The broader implication is that in late 2026 the scarce resource in agentic software delivery is trustworthy evidence that code is right, not code generation. Benchmarks are contaminated, vendor reviewers are opinions, and auditors cannot reconstruct what an agent saw. An open project that turns "the agent says tests pass" into a signed, tamper-evident claim anyone can check is aiming at the real bottleneck. It also gets better as the author agents improve.
